# 公众号每日监测（v1 — 知识库自动联动）

**重要：所有输出必须全部使用中文。**

## 目标

本技能用于把微信公众号文章纳入仓库内的标准监测流程：

1. 获取一个或多个 `mp.weixin.qq.com` 文章链接
2. 运行 `scripts/wechat_article_pipeline.py` 抓取文章、下载图片、输出 Markdown
3. 根据 `docs/superpowers/specs/公众号每日监测.md` 的规则完成 `P0` 到 `P4` 分类
4. 自动刷新知识库，让新文章进入 `source_md` 检索路径
5. 产出结构化监测报告、紧急提醒、日报摘要、周报候选和归档轨迹

## 触发语

以下请求优先触发本技能：

- "检查公众号最新文章"
- "监测公众号每日更新"
- "抓取这篇微信公众号文章并入库"
- "生成公众号日报"
- "生成公众号预警"
- "把公众号文章同步到知识库"

## 前置条件

1. 在仓库根目录执行
2. 使用当前项目的 Python venv
3. `requests` 与 `beautifulsoup4` 可用；如缺失，安装：

```powershell
uv pip install --python .\.venv\Scripts\python.exe requests beautifulsoup4
```

4. 如需自动发现文章链接，当前运行环境应能访问 `wechat-router/wechat-decrypt/` 的 MCP 能力

## 输出目录

所有抓取结果保存到：

```text
docs/医院材料学习/公众号每日监测/YYYY-MM-DD/<公众号名>/<NN_文章标题>/
```

每篇文章目录至少包含：

- 清洗后的 Markdown 文件
- `metadata.json`
- 下载后的正文图片（`images/`）

可选输出：

- `source.html`（仅在需要调试正文清洗时保留）

## 取链模式

### 模式一：自动发现（首选，best-effort）

优先使用 `wechat-router/wechat-decrypt/` 相关 MCP 能力，查找监测源公众号最近发送的文章链接。

执行要求：

1. 先筛查监测源公众号最近消息或链接消息
2. 只保留实际可访问的 `mp.weixin.qq.com` 链接
3. 如果当前运行环境只能看到标题、摘要或链接卡片，但无法读出真实 URL，**不要猜测链接**，立即切换到手动模式

### 模式二：手动输入（稳定兜底）

当自动发现不可用、MCP 无法提供实际 URL、或操作者已直接给出链接时，使用手动模式：

1. 让操作者提供 1 个或多个文章 URL
2. 只接受 `mp.weixin.qq.com` / `weixin.qq.com` 域名
3. 逐条抓取并纳入同一次监测报告

## 优先级规则

| 优先级 | 关键词 / 场景 | 处理方式 |
|------|---------------|---------|
| `P0` | 医保局令、实施细则、目录调整、飞检启动、骗保处罚、取消定点、价格/编码调整 | 立即预警，附 3 行摘要 |
| `P1` | 针刺/艾灸/推拿合规、病历书写、四单一致、审核/扣款/拒付、DRG/DIP | 纳入当日摘要 |
| `P2` | 中医馆运营案例、营收模型、团队管理、患者运营、信息化/AI 工具 | 纳入周报候选 |
| `P3` | 行业数据、培训、继续教育、设备/耗材动态 | 归档，可搜索 |
| `P4` | 养生科普、广告推广、低价值软文 | 归档或过滤 |

### 自动判定规则

按以下优先级依次判定：

```text
IF 标题含 ("医保局" AND "令") OR "4月1日" OR ("飞检" AND "启动")
  -> P0

IF 标题含 ("骗保" OR "处罚" OR "罚款" OR "取消定点")
   AND ("中医" OR "门诊" OR "诊所")
  -> P0（警示案例）

IF 标题含 ("针刺" OR "艾灸" OR "推拿")
   AND ("医保" OR "合规" OR "收费")
  -> P1

IF 标题含 ("中医馆" OR "门诊")
   AND ("营收" OR "运营" OR "案例")
  -> P2

其他命中监测关键词的文章
  -> 按对应优先级分类

未命中明确低优先级词但仍值得留档的内容
  -> P3
```

## 执行流程

### 第一步：确定取链模式

先判断本次使用自动发现还是手动输入。

### 第二步：收集文章 URL

- 自动发现模式：收集成功解析出的真实 `mp.weixin.qq.com` 链接
- 手动模式：直接接收操作者提供的 1 个或多个链接

如果最终没有可用 URL，停止并说明本次未执行抓取。

### 第三步：运行抓取脚本

优先使用以下命令：

```powershell
python scripts/wechat_article_pipeline.py "<url1>" "<url2>" --output-dir "docs/医院材料学习/公众号每日监测" --save-html --refresh-kb
```

说明：

- 支持一次处理多个 URL
- `--save-html` 用于保留调试所需的清洗 HTML
- `--refresh-kb` 会在抓取完成后自动执行最小知识库刷新流程

### 第四步：读取监测报告

脚本执行后，读取 `docs/医院材料学习/公众号每日监测/_reports/` 下最新的 JSON 报告，提取：

- `urgent_alerts`
- `daily_summary`
- `weekly_candidates`
- `archive_trail`

### 第五步：整理并输出

向用户返回：

1. 本次成功抓取的文章数
2. 每篇文章的标题、公众号、优先级、本地路径
3. `P0` 紧急预警
4. `P1` 当日摘要
5. `P2` 周报候选
6. `P3/P4` 归档记录
7. 知识库刷新状态

## 知识库联动

本技能默认把新文章视为 `docs` 模式下的原生 Markdown 输入。

如使用 `--refresh-kb`，脚本会自动执行最小刷新流程。其等价命令为：

```powershell
python scripts/update_kb_manifest.py
qmd collection remove source_md 2>$null
qmd collection add "docs/医院材料学习" --name source_md --mask "**/*.md"
```

注意：

- `docs/医院材料学习/公众号每日监测/` 下新增的 Markdown 属于 `source_md` 刷新范围
- 如果本次还需要 PDF/DOCX/PPTX 转换或 Wiki 刷新，不要在本技能里重复实现，改为复用 `knowledge-base-update` 技能

## 输出要求

### P0 紧急预警

每条 `P0` 文章至少输出：

- 标题
- 来源公众号
- 命中关键词
- 3 行摘要
- 原文链接
- 本地路径

### P1 每日摘要

按条目汇总为当日阅读清单，标注"建议当日处理"。

### P2 周报候选

按主题或运营价值归类，标注为周报候选。

### P3 / P4 归档轨迹

保留标题、来源、分类、本地路径，便于后续搜索或过滤。

## 失败处理

- URL 非微信文章域名：直接报错，不继续
- 页面被删除、受限或需要登录：记录失败原因并跳过该链接
- 自动发现拿不到真实 URL：明确说明已退回手动模式
- KB 刷新失败：保留文章抓取结果，但在输出中标注"知识库刷新未完成"
